
# EMOCD Engineering Programme Dossier v1.0

> **The objective of the EMOCD Engineering Programme is not to produce the most novel deployment system; it is to demonstrate disciplined, evidence-based engineering while laying the foundation for future aerospace research.**

# 1. Mission

The EMOCD Engineering Programme exists to:

- Develop a programmable electromagnetic CubeSat deployment architecture through rigorous engineering.
- Produce a final-year thesis.
- Produce an IEEE publication.
- Build a professional engineering portfolio.
- Establish the foundation for long-term aerospace research.

The programme is committed to engineering truth rather than preserving any particular implementation.

# 2. Engineering Programme vs Deliverables

## Engineering Programme

The programme is intentionally open-ended.

Any subsystem, assumption, architecture or mission may be questioned if supported by stronger evidence.

Nothing is protected from revision.

## Phase I Deliverables

The following are developed against a frozen engineering baseline:

- Portfolio repository
- Final-year thesis
- IEEE publication

During Phase I, improvements should primarily focus on:

- validation
- documentation
- manufacturability
- engineering quality
- reproducibility
- error correction

Fundamental redesigns should normally be deferred to the next baseline unless a critical engineering flaw is discovered.

# 3. Repository Strategy

## Repository 1 — EMOCD (Flagship)

Audience:
- Aerospace companies
- Internship reviewers
- Engineering recruiters

Purpose:
Demonstrate engineering capability and systems thinking.

Contains:
- Documentation
- CAD
- Simulations
- Validation
- ADRs
- Literature review
- Repository roadmap
- Links to thesis and publication

This repository is the authoritative engineering record during Phase I.

Do not split or substantially reorganise it without explicit approval.

## Repository 2 — IEEE Companion (Future)

Audience:
Researchers.

Purpose:
Reproducibility.

Contains:
- Final manuscript
- Figures
- Simulation inputs
- Supporting calculations
- Supplementary material

Derived from the flagship repository.

## Repository 3 — Thesis Companion (Future)

Audience:
University.

Purpose:
Academic submission.

Contains:
- Thesis
- Appendices
- References
- Viva material
- University-specific documents

Derived from the flagship repository.

## Repository 4+ — Independent Research

Created only after work becomes a reusable engineering project beyond EMOCD.

Examples:

- Electromagnetic Linear Motors
- CubeSat Dynamics Toolkit
- Vacuum Test Platform
- Orbital Deployment Optimisation
- Engineering Utilities

# 4. Repository Governance

The flagship repository is a deliverable.

Repository stability is a design requirement.

Never create new repositories merely because work can be modularised.

Only recommend a new repository when:

1. It has become an independent engineering project.
2. It has value outside EMOCD.
3. Keeping it inside EMOCD would reduce clarity.
4. Explicit approval has been given.

# 5. Engineering Philosophy

- Physics over intuition.
- Evidence over opinion.
- Simplicity over cleverness.
- Reliability over peak performance.
- Manufacturability over elegance.
- Flight qualification over novelty.
- Architecture over mechanisms.
- Honest documentation of failures.
- Finished engineering before better engineering.

# 6. Literature Philosophy

The literature review exists to identify:

- Better ideas
- Competing approaches
- Hidden assumptions
- Previous failures
- Engineering tradeoffs

The dossier should preserve analyses of relevant deployment papers and maintain EMOCD's evolving position within the literature.

# 7. Validation Philosophy

Concept → Analysis → Simulation → Prototype → Experiment → Repeatability → Manufacturability → Flight Qualification

Every feature should have a path toward validation.

# 8. Cross-Industry Learning

Continuously study:

- Industrial automation
- Robotics
- CNC systems
- Semiconductor manufacturing
- Linear motors
- Particle accelerators
- Maglev
- Precision positioning
- Vacuum engineering
- EV power electronics

# 9. Engineering Evolution Policy

The Engineering Programme remains open to questioning every assumption.

The deliverables remain bound to a defined scope.

The programme is bound to truth.

The deliverables are bound to completion.

# 10. Success

Phase I succeeds when:

- Thesis completed.
- IEEE paper submitted.
- Flagship repository demonstrates professional engineering practice.
- Portfolio supports aerospace employment.

Phase II begins after Phase I and may fundamentally redesign any aspect of the programme.
